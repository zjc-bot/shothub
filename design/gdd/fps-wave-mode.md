## 0. 设计总览

**一句话**：在现有 60×60 pastel 世界中，玩家持一把程序化步枪，抵御 5 波人形持枪 bot 的进攻；全部歼灭即胜利，HP 归零即失败。

**与现有 demo 的关系（取舍决策）**：进入页提供两个选项——

| 选项 | 内容 | 理由 |
|---|---|---|
| `[1] 波次挑战` | 本 GDD 的新模式 | 主玩法 |
| `[2] 观光模式` | **现有 demo 原样保留**（推箱/炮台/眼球/灯塔/手电调试快捷键） | 不破坏既有物理演示与 selftest 资产，两个模式共用同一引擎与世界构建管线 |

挑战模式复用 `world.build_world` 的地形/围墙/灯塔/木箱，但**不生成炮台（Turret）与漂浮眼球（Eye）**：炮台弹道与 bot 弹道会在视觉上混淆敌我火力，且炮台只锁定玩家会制造设计外的第三方威胁（取舍记录，供 ADR 引用）。观光模式完全照旧。

**模式实现方式**：`build_world(app, mode)` 增加模式参数；挑战模式在基础世界之上叠加「战斗层」——掩体布局（§6）+ 刷怪点 + WaveManager + bot。两种模式均纳入 `--selftest` 链路（§8）。

## 1. 核心循环与游戏流程状态机

### 1.1 核心循环（10 秒粒度）

观察战场 → 瞄准射击（控扩散/控弹药）→ 借掩体规避 bot 火力 → 脱战呼吸回血 → 清波 → 间隙补给 → 迎接下一波（更硬/更准/更多）。

### 1.2 状态机

```
                ┌──────────────────────────────────────────┐
                │                                          │
   启动 ──► TITLE（进入页）──[1]──► COMBAT（第1波刷怪/交战）
                │                      │
               [2]            清完全部bot│
                │                      ▼
                │              INTERMISSION（8s 补给喘息）
                │                      │ 倒计时结束且未到第5波后
                │                      ▼
                │                COMBAT（下一波）──┐
                │                      │           │ 玩家 HP≤0
                │            清完第5波 │           ▼
                │                      ▼       RESULT_LOSE（结算页）
                │                 RESULT_WIN（结算页）
                │                      │  [R] 重开（回 TITLE）
                ▼                      ▼
             EXPLORE ◄────────── 两结算页 [Esc] 退出
            （现有 demo，快捷键照旧，[Esc] 释放鼠标/退出）
```

### 1.3 各状态定义

| 状态 | 世界模拟 | 玩家控制 | 输入/转出条件 |
|---|---|---|---|
| TITLE | 世界已构建但 bot 不生成；相机固定在出生点缓速环视（yaw 0.05 rad/s 自动旋转，demo 级即可） | 冻结（不响应 WASD/鼠标视角） | `[1]`→COMBAT（先进入 INTERMISSION 倒计时 3s 再刷第 1 波）；`[2]`→EXPLORE |
| COMBAT | 全量模拟；WaveManager 按波次表刷怪 | 全控制 + 开火 | 场上 bot 全灭且本波刷怪完毕 → INTERMISSION（若刚清完第 5 波 → RESULT_WIN）；玩家 HP≤0 → RESULT_LOSE |
| INTERMISSION | 模拟继续（无 bot）；补弹、回血 +30、波次横幅 + 倒计时 | 全控制（可走位抢位） | 倒计时 8s 结束 → COMBAT（下一波） |
| RESULT_WIN / RESULT_LOSE | 模拟冻结（实体不 update，渲染继续） | 冻结 | `[R]` → TITLE（`reset_world` 全量重建，复用现有 R 键链路）；`[Esc]` → 退出 |
| EXPLORE | 现状 demo | 现状 | 现状快捷键（Tab/F/H/R…） |

**鼠标捕获**：TITLE/RESULT 页释放鼠标（`release_mouse`，显示光标）；进入 COMBAT/EXPLORE 时捕获。沿用 `core.py` 现有 capture/release API，无需引擎改动。

## 2. 射击系统

### 2.1 持枪视角模型（view-model）

程序化拼装枪，作为纯视觉实体（`cast_shadow=False`），每帧由游戏逻辑同步到相机局部空间（与 Turret 每帧同步炮管同一模式，引擎无父子层级）：

| 部件 | 尺寸 (w,h,d) m | 相对相机局部偏移 (右, 上, 前) | 配色（沿用 visual-style） |
|---|---|---|---|
| 机匣/枪身 | 0.09 × 0.13 × 0.52 | (0.22, -0.20, 0.45) | 冷深灰 (0.40, 0.42, 0.46)，即炮管色，规格中"唯一冷色暗部" |
| 枪管 | 0.05 × 0.05 × 0.30 | (0.22, -0.17, 0.72) | 同上，shininess 72 / spec 0.70 |
| 握把 | 0.07 × 0.16 × 0.09 | (0.22, -0.31, 0.38) | 暖棕木 (0.82, 0.58, 0.34) |
| 弹匣 | 0.06 × 0.15 × 0.08 | (0.22, -0.31, 0.50) | 琥珀金 (1.00, 0.80, 0.40)，点缀色，兼作"弹药视觉提示" |

摆动感（全部帧率无关，指数阻尼 + 正弦叠加）：
- **呼吸/移动摆动（bob）**：位移摆动 = 玩家水平速度 / run_speed × 振幅 0.012m，相位 ω=9 rad/s，作用于上/右两轴；静止时振幅衰减到 0.003m（呼吸感）。
- **视角滞后（sway）**：枪的位置向目标偏移做 `k = 1-exp(-14·dt)` 阻尼跟随，鼠标转得越快枪越"拖"，上限 0.03m。
- **开火后座**：枪沿局部 -前 方向瞬移 0.03m，0.09s 内阻尼回位（`k = 1-exp(-18·dt)`）。
- **穿墙规避**：每帧从眼睛向前 raycast（复用 §2.2 新增的射线能力），命中距离 < 0.75m 时枪整体后拉到 命中距-0.1m 处——demo 级防穿模，复用同一射线函数，零额外系统。
- **枪口火光**：不新增灯（MAX_SPOTS 已满 2/3，余量必须保留）。方案 = Turret.flash 同款：开火后 0.05s 内把枪管 color 换为自发光琥珀 `(1.0, 0.82, 0.45)`，并在枪口位置瞬时显示一个 `unlit=True, cast_shadow=False` 的小 box（0.07³）0.04s。

### 2.2 开火方式：Hitscan（决策记录）

**决定：玩家武器与 bot 武器均为 hitscan（瞬时射线判定）。**

| 备选 | 结论 | 理由 |
|---|---|---|
| **Hitscan（采用）** | ✅ | ① CF 挑战模式手感即 hitscan，指哪打哪；② 判定确定性强，selftest 可精确断言（"瞄准头部开火 → 爆头击杀"）；③ 无隧道效应风险；④ 新增 ray vs AABB（slab 法）约 40 行进 `math_utils.py`，一次实现四处复用：玩家射击、bot 视线（LOS）、bot 射击、view-model 防穿墙 |
| 物理弹道（复用 Projectile） | ✗ | 弹速 13m/s × 步长 1/120s ≈ 0.11m/步，打 0.34m 的爆头盒会出现抽样落空；若要提速到步枪手感（>200m/s）则必须做 CCD，工作量与风险都超 demo 量级。Projectile 保留在观光模式作物理演示 |

**新增引擎能力 E2（程基岩落地）**：
```python
# engine/math_utils.py 新增
def ray_aabb(origin, dir, center, half):
    """slab 法射线 vs AABB，返回最近进入距离 t 或 None。dir 需归一化，t>=0。"""
```
game 层封装 `raycast_world(physics, origin, dir, max_dist)`：遍历 `physics.bodies` 中 `is_static` 的碰撞体取最近 t（墙/地面/掩体/箱子全部天然支持，含可推箱——子弹能被木箱挡，正确且免费）。

### 2.3 枪械参数（步枪 "MW-1"）

| 参数 | 值 | 说明 |
|---|---|---|

**扩散模型**（角度制，最终弹道 = 视线方向在圆锥内均匀随机偏转）：
```

bloom  : 每发射击 +0.35°，上限 3.0°；停射 0.25s 后以 8°/s 线性收敛
move_mult : 站立 1.0 / 走动 1.6 / 疾跑 2.2 / 空中 2.5
```

## 3. 伤害与血量模型

### 3.1 玩家

- **HP = 100**，无护甲。
- 受击来源：bot hitscan 子弹（伤害随波次，§5）。
- **脱战回血（采用）**：最后一次受击后 4.0s 未再受击，则以 10 HP/s 回复至 100。
  - 决策理由：demo 无血包/无队友，5 波连续交战不回血挫败感极强；CF 挑战模式亦有呼吸回血类节奏设计。回血机制同时鼓励"掩体喘息"这一核心走位行为，与 §6 掩体布局形成闭环。
- 受击即打断并重启 4.0s 计时。

### 3.2 bot 血量与伤害倍率

| 部位 | 判定盒（数学 AABB，非物理体） | 倍率 | 26 基础伤害实值 |
|---|---|---|---|
| 头 | 中心 = bot 位置 + (0, 1.66, 0)，半尺寸 (0.18, 0.17, 0.18) | ×2.5 | 65 |
| 躯干+腿 | 中心 = bot 位置 + (0, 0.90, 0)，半尺寸 (0.32, 0.90, 0.26) | ×1.0 | 26 |

bot 血量随波次（§5 表）：40 → 100；精英 ×1.6。

### 3.3 爆头判定的工程方案（决策记录）

**约束**：引擎一个 Entity 只能挂一个 PhysicsBody，且物理世界无碰撞过滤——若给头部挂独立小物理体，它会与 bot 自身躯体碰撞互推。

**决定：hitscan 不经过物理世界。** 战斗系统（CombatManager）为每只存活 bot 每帧维护两个**纯数学 AABB**（上表），射击判定流程：

```
1. raycast_world(静态体) → t_wall        # 掩体/墙/箱子遮挡
2. 对每只 bot：ray_aabb(头盒) → t_head；ray_aabb(躯干盒) → t_body
3. 取 t_hit = min(所有 bot 的头/躯干命中)；若 t_hit < t_wall 且 t_hit < max_dist → 命中
   命中部位 = 较小 t 对应的盒（头优先：t_head ≤ t_body + 0.05 时算爆头，补偿盒间重叠）
```

bot 的 PhysicsBody（全身 AABB，half=(0.32, 0.91, 0.32)，mass=65）继续承担移动碰撞/推挤/被玩家推开的职责，与命中判定完全解耦。零引擎改动、零碰撞过滤需求。

## 4. 人形 bot 设计

### 4.1 几何拼装规格（零外部资源，Turret 同步模式）

总高 ≈ 1.84m。所有部件为 `box_mesh` 纯视觉实体（仅躯干挂物理体），bot 实体每帧按自身 transform 同步全部部件（位置 = bot 原点 + 局部偏移经 yaw 旋转；腿部叠加步行摆动 pitch）。

| 部件 | 尺寸 (w,h,d) m | 局部偏移 (x 右, y 上, z 前) | 配色（pastel 合规：明度 0.6~0.95、通道差 ≤0.45） |
|---|---|---|---|
| 头 | 0.34 × 0.32 × 0.34 | (0, 1.66, 0) | 肤色 (0.93, 0.80, 0.66) |
| 躯干 | 0.60 × 0.70 × 0.34 | (0, 1.15, 0) | 普通兵：灰蓝绿 (0.52, 0.62, 0.60)／**精英：珊瑚红 (0.90, 0.42, 0.38)** |
| 腿 ×2 | 0.22 × 0.80 × 0.26 | (±0.14, 0.40, 0) | (0.58, 0.62, 0.70) |
| 臂 ×2 | 0.16 × 0.58 × 0.20 | (±0.38, 1.18, 0.06) | 同躯干 |
| 枪 | 0.11 × 0.15 × 0.80 | (0.30, 1.22, 0.42) | 冷深灰 (0.40, 0.42, 0.46)，与玩家枪同色——战场敌我靠**躯干颜色**区分（橙=玩家方已有、灰蓝绿/红=敌） |

材质：躯干/四肢 shininess 20 / spec 0.15（哑光布料感）；头 24 / 0.20；枪 72 / 0.70。阴影预算：**仅躯干+头 `cast_shadow=True`**，四肢与枪 False（同屏 5 bot × 7 部件 × 2 盏阴影灯下的 draw call 控制，见 §10 风险 R2）。

**动作表现**（无骨骼、无动画系统约束内）：
- 步行：双腿 pitch = ±sin(相位)·25° 反向摆动，相位速度 = 移速 × 3.2；手臂 ±8° 小摆。
- 瞄准：整枪随躯干 yaw 指向玩家，开火时枪身 color 提亮（Turret.flash 模式）。
- 受击/死亡：见 §2.4。

### 4.2 AI 行为状态机（demo 级可实现）

```
SPAWN ──0.8s──► APPROACH ──距离≤14 且 LOS──► ENGAGE
                  ▲                            │
                  └──── 失去 LOS >1.5s ────────┤
                  │                            │ HP<30% 且波次≥3
                  │                            ▼
                  └────────── REPOSITION ◄── STRAFE 内置
                任意状态 HP≤0 → DEAD（倒地动画 → scene.remove）
```

| 状态 | 行为 |
|---|---|
| SPAWN | 0.8s 入场（自发光边框感：躯干 unlit 闪烁 2 次），可被打但不开火 |
| APPROACH | 直线走向玩家，速度 3.2 m/s（疾跑玩家 8.2，永远追得上走位但追不死风筝）；避障 = 两根须线 raycast（前方 ±35°、长 3m，复用 E2），命中静态体则沿命中法线切向绕行；bot 间碰撞由物理体互推天然分离（等质量动态 AABB，免费） |
| ENGAGE | 距离 8~14m 巡航（<8 后退、>14 前压），叠加侧向游走（2~3s 随机换向，速度 1.8）；瞄准 0.5s 后开始点射：**3 发 burst、发间隔 0.12s、burst 间隔 1.1~1.6s 随机**；每 burst 第一发强制偏移 ≥ 误差角×0.7（"警告弹"，给玩家反应窗口，CF 式仁慈） |
| REPOSITION | 失去 LOS 时向最近一个"能看见玩家的预计算点"移动（预计算点 = §6 掩体间隙的 8 个固定导航点，建图时硬编码坐标表，无 A*）；到达或恢复 LOS 后回 ENGAGE |
| DEAD | 见 §2.4；计击杀数，爆头单独计数 |

**取舍说明（不做全身寻路/掩体 AI）**：60×60 开阔图 + 稀疏掩体 + 须线避障 + 固定导航点，在 demo 量级已能呈现"会包抄、会绕墙"的观感；A* 导航网格与掩体评估属超 scope，列入增强档（§9）。

### 4.3 射击精准度模型

```
误差角 err(度) = wave_err × (1 + dist/40) + move_penalty
  wave_err    : 波次基准（§5 表，7.0° → 3.5°）
  dist        : 与玩家距离（远则更不准）
  move_penalty: 玩家水平速度 >6 m/s（疾跑/跳跃）时 +1.2°，否则 0
每发在 err 圆锥内均匀随机；命中判定 = bot 枪口 → 偏移后方向 的 hitscan
（同样先 raycast 静态体：bot 会打中掩体，玩家躲矮墙后自然安全——掩体有效性的机制保证）
```

## 5. 波次系统

### 5.1 波次表（5 波）

| 波 | 总数 | 单 HP | 精英数（HP×1.6） | 单发伤害 | 基准误差角 | 刷出间隔 | 同屏上限 | 刷怪点数 |
|---|---|---|---|---|---|---|---|---|
| 1 | 4 | 40 | 0 | 6 | 7.0° | 2.2s | 3 | 2 |
| 2 | 6 | 55 | 0 | 7 | 6.0° | 2.0s | 4 | 2 |
| 3 | 8 | 70 | 1 (HP 112) | 8 | 5.0° | 1.8s | 4 | 3 |
| 4 | 10 | 85 | 2 (HP 136) | 9 | 4.2° | 1.5s | 5 | 3 |
| 5 | 12 | 100 | 3 (HP 160) | 10 | 3.5° | 1.3s | 5 | 3 |

数值校验：第 1 波 40HP = 躯干 2 枪 / 爆头 1 枪；第 5 波普通 100HP = 躯干 4 枪 / 爆头 2 枪；精英 160HP = 躯干 7 枪 / 爆头 3 枪。全程备弹 120+30 每波间隙补满，弹药压力出现在第 4~5 波连射浪费时——符合"控枪"教学曲线。

### 5.2 刷怪点轮换规则

- 6 个刷怪点（§6 图）：SP1~SP4 四角 (±24, ±24)、SP5 (0,-26)、SP6 (0, 26)。
- 每波开始时：按"距玩家当前位置"从远到近排序，**取最远的前 N 个**（N=波的刷怪点数），且与上一波所用集合**不得完全相同**（相同时把最远点换成次远未用点）。
- 单个刷怪点连续两次刷怪间隔 ≥ 1 只（同点不连刷，防叠罗汉）。
- 刷怪点必须有到玩家的可行视线走廊（§6 布局已保证，见坐标图）。

### 5.3 间隙与胜负

- **INTERMISSION 8s**：横幅 "第 N 波 已肃清 · 下一波 8s"，倒计时逐秒更新；进入间隙即：弹匣补满 30、备弹重置 120、HP +30（≤100 封顶）。
- **胜利**：第 5 波全灭 → RESULT_WIN。
- **失败**：任意时刻玩家 HP ≤ 0 → RESULT_LOSE（记录存活波次）。
