## ENG-006：退出确认页 + 回标题页（不再需要杀进程）

用户诉求："设计退出页面，游戏结束后退回首页，避免要结束进程"。查出两个真问题：① `Esc` 在鼠标未捕获时直接 `self.running = False` 杀进程，无任何缓冲；② 事件分支里 `continue` 掉了 KEYDOWN，**Esc 永远进不了 Input**，游戏层根本看不到它。③ 额外发现**观光模式是死胡同**——`_handle_shortcuts` 里 `R` 只调 `reset_world()` 改世界不改状态，没有任何键能回标题页。

- **引擎加钩子**：`Engine.on_escape()`（子类返回 True=消费 Esc，默认 False 走原逻辑）+ `Engine.request_quit()`。`_process_events` 的 Esc 分支改为 `if not self.on_escape(): <原行为>`。这是让游戏层能响应 Esc 的**唯一**途径（Esc 不进 Input）。
- **新增状态 `ST_QUIT`**：标题页/两个结算页按 Esc 进入；卡片给三个选项 `[Enter] 确认退出 / [Esc] 返回上一页 / [T] 回到标题页`。`_quit_return` 记住来源状态，Esc 原路返回。`simulation_active()` 把 ST_QUIT 一并冻结（读确认框时不该被 bot 打死、也不该继续跑物理）。`request_quit()` 是**唯一**真正结束进程的入口。
- **`App.back_to_title(from_state)`**：抽公共回首页路径（`mode="challenge"` → `reset_world()` → `_enter_state(ST_TITLE)`），结算页 `R`/`T` 与退出页 `T` 共用。
- **观光解死胡同**：EXPLORE 增 `K_t` → `back_to_title()`；结算页增 `K_t`（原 `R` 是"直接重开同一模式"，`T` 是"回进入页换模式"，语义区分开）。
- **交战/间隙/观光不拦 Esc**：这些状态鼠标处于捕获态，引擎默认只释放鼠标（防误触），第二次才弹确认页。COMBAT/INTERMISSION/EXPLORE 的 `on_escape()` 返回 False。
- **验证**：selftest 21/21 PASS；4 种来源状态 Esc 均进确认页且 `running=True`；确认页 Esc 取消/Enter 退出/T 回标题三条分支逐一验过；结算页 R→TITLE 世界干净（HP=100、bot=0）；退出卡 320×103 居中偏差 0.00、模拟已冻结（`_qa_shots/15`）。
- **文案同步**：README 键位表（全局/结算/观光三处）+ 新增「退出确认页」小节 + FAQ 坑位 3 重写；游戏内 `H` 按键总览补 3 行。

## ENG-007：物理真实感 + 射击反馈（三模块）

任务书按 Ursina 写的（`add_force`/`Rigidbody`/`Panel`/`render_order`），本项目是 pygame-ce + moderngl，需自行映射。**核查后发现三模块有一半已存在**：hitscan（`ray_aabb` slab）、后座回正（`CameraRig.kick`）、ADS（0.8s/FOV 62→18）、击退（`k/(mass+armor)`）都是现成的。真正新增/修正的是 5 项：姿态系统、狙击专属后座+开镜减震、狙击专属击退、火花、弹痕。

### 模块一 · 角色姿态（`game/player.py`，全新）

- 三态 `STAND/CROUCH/PRONE`，`POSTURE_HALF_Y`/`POSTURE_EYE`/`POSTURE_SPEED` 三张表集中可调：站立 0.90/0.72/1.00、下蹲 0.55/0.37/0.52、趴下 0.26/0.08/0.20。
- **平滑不瞬移**：半高走指数逼近 + `POSTURE_MAX_BLEND_PER_FRAME=1.8 m/s` 限速。限速是必需的——纯指数在掉帧（大 dt）时一步跳完，视觉上就是瞬移。眼高走指数（摄像机平滑升降）。
- **趴下更稳**：`stability()` 返回 0.25，`Weapon._sync_view_model` 用它压缩 bob 振幅与 sway 上限。非站立禁疾跑/禁跳。
- **起身受阻**：`_can_reach` 用 `aabb_vs_aabb` 测"新增占据体积"（脚底→目标头顶+间隙）是否与静态体重叠。踩过的坑：① 最初用 `ray_aabb` 向上探，但 hitscan 语义下"起点在盒内"恒返回 0.0 → 任何姿态都误判受阻；② 只探"当前头顶以上"会在玩家贴着掩体时误判可起身；③ 探针盒心放在 base 上等于起点在盒内。最终解法是纯 AABB 相交测试。玩家自身物理体由 `world.build_world` 注入 `player._physics`，为 None 时退化为"总能起身"。
- 键位：`Ctrl` 按住下蹲 / `C` 切换下蹲 / `Z` 切换趴下（app.on_update 状态分发前统一处理，松开 Ctrl 自动回站）。HUD 左下显示姿态+移速百分比。
- **坑**：`posture` 名的到位判定原用绝对 eps 0.002，对半高 0.26 的趴姿过宽 → 过渡早期就判定"已到位"。改比例判据 `max(0.002, t*0.02)`。

### 模块二 · 狙击手感（`game/weapon.py`、`engine/camera.py`）

- 狙击后座从"硬编码复用步枪值"改为专属：**腰射 1.90°/±0.30°**（步枪 0.35°/0.12° 的 5.4×/2.5×）。
- `ads_recoil_scale=0.15`：开镜后座降到 15%；`ads_hip_sens_scale=0.35`：开镜鼠标灵敏度降到 35%（1:1 镜）。`CameraRig.update` 新增 `sens_scale` 形参。
- `CameraRig.kick_recovery_scale(factor)`：开火时把回弹速率降到 0.55（腰射），后坐"坐"在镜头上更久；无残留后座时自动回 1.0。

### 模块三 · 命中特效（`game/effects.py` 全新 + shader/renderer 扩展）

- **弹痕需要 alpha 才能淡出** → 主 pass 不开混合（alpha 恒 1），故新增 **2.5 decal pass**（BLEND + DEPTH_TEST + depth_mask off），shader 加 `u_alpha` uniform，`MeshRenderer` 加 `decal`/`alpha` 字段。主 pass 跳过 `r.decal` 实体。
- 弹痕贴图 `graphics/texture.decal_bytes()`：RGBA，弹孔+7 条放射裂纹+边缘羽化，零外部资源。
- **坐标推导（花了几轮才对）**：`M = T·Ry(yaw)·Rx(pitch)·Rz(roll)`，取 roll=0 时局部 +Y 映为 `(cos yaw·sin p, cos p, sin yaw·sin p)`，故 `pitch=acos(n.y)`、`yaw=atan2(n.x, n.z)`。试过 `atan2(n.x,-n.z)`、`atan2(-n.x,n.z)`、`asin` 变体都只能对上部分方向——最后用真实 `Transform.model_matrix()` 穷举 7 个方向验证，误差 2.2e-16。
- `aabb_surface_normal()`：取命中点最贴近的六个面之一。**不需要**剔除射线背后的面——命中点由 `origin+dir·t` 得出天然落在进入面上。最初加了"只取射线前方"过滤反而在擦棱角时选错边。
- **对象池有界**：`MAX_DECALS=40`/`MAX_SPARKS=64`，超限时把池里最旧的**原地改属性复用**（`revive()`），不走 Scene 延迟删除队列。实测 2000 次命中实体数稳定不涨，单次 0.018ms。
- 弹痕只挂静态面：bot 身上只出火花（尸体消失后弹痕会悬空），动态木箱同理（贴面弹痕会脱节）。
- 击退参数化：`player_shoot(knockback=)`，`KNOCKBACK_SNIPER=300` vs 步枪 110。实测同一 bot 速度增量 1.22 → 3.33。

## ENG-007：HUD 贴屏 quad 顶点顺序（只在真窗口可见的 HUD 变形）

用户转来外部诊断：「深色半透明背景板不是矩形，像两个梯形/三角形拼接，中间交汇成 X / 蝴蝶结，有接缝与阴影断层，文字被截断」。对方给的归因（Ursina `Panel()` / `vertices` / `render_order` / Z-fighting）与本库不符（本库无 Ursina，`vertices` 只存在于 `engine/mesh.py` 的 3D 网格），但**症状描述是准确的**。

- **复现环境**：本机其实能建真 GL 上下文（`GL_RENDERER: Intel(R) Graphics`，3.3 Core）。取帧方式：真窗口 + `pygame.display.flip()` 前读回默认帧缓冲（或把 `Renderer.ctx` 换成 FBO 代理）；窗口用 `SDL_VIDEO_WINDOW_POS` 放屏幕外、`Engine.capture_mouse` 打桩，不打扰用户。
- **根因**：`graphics/renderer.py` HUD 全屏 quad 的 `hud_verts` 顶点顺序写成 左下→右下→右上→左上。TRIANGLE_STRIP 的两个三角形是 `{v0,v1,v2}` 与 `{v1,v2,v3}`，该顺序下两者都落在屏幕右半边，左侧留下**以画面中心为顶点的楔形空洞**——HUD 只覆盖视口 **75.00%**，中间那一行会吃掉左侧整个半屏，于是贴左/居中的卡片被斜边切、看起来就是「蝴蝶结 / 两块梯形拼接 / 接缝」。**修法**：改为 Z 字序 左下→右下→左上→右上（UV 配对不变），实测铺屏率 75.00% → **100.00%**。
- **排除项（都有实测数据）**：`hud_tex` 读回逐像素正确（上传/通道顺序无问题）；换成**常量色片段着色器**仍复现缺口 → 与纹理采样/premultiply/blend 无关；宽 1282（非 4 的倍数）也不斜切 → 与行对齐无关；逻辑像素与 framebuffer 尺寸实测一致 → 与 DPI/viewport 无关；HUD pass `enable_only(BLEND)` 关掉深度测试 → Z-fighting 本就不可能。
- **为何历次排查全漏**：该缺陷只存在于 GL 贴屏那一步。`--selftest` 无窗口无 GL；`_qa_shots/03,07,08,09` 那批「3D 全黑只有 HUD」的截图正是**没走 GL** 的 2D 合成证据——它们的 HUD 必然正常。ENG-005 的布局实测（尺寸/居中/夹紧）全部为真，只是覆盖不到这一层。
- **新增回归检查**：`engine/qa_gl.py` + `python main.py --glcheck`。真窗口（屏幕外、冻结场景）把 HUD 换成「纯色底 + 四角标记色」图案，读回默认帧缓冲断言 ①铺屏率 100% ②四角朝向正确；退出码 0/1，无 GL 环境自动 SKIP。**已反向验证**：故意写回旧顶点顺序 → 75.00%、左侧两角 MISMATCH、退出码 1。
- **验证**：`--glcheck` PASS（100.00%，四角 OK）+ `--selftest` 21/21 PASS；真窗口合成截图 `_qa_shots/17_realwin_title_help.png`、`18_realwin_combat.png`（本仓库首批「GL + HUD 合成」真图，此前从未有过）。HUD 落点实测：常驻卡 x 16..348、居中卡 x 380..899（中心 639.5≈640），逐行宽度变化仅来自 12px 圆角。
